# Firebase Authentication setup for Testora

This branch replaces the mock email/password authentication repository with Firebase Authentication while preserving the existing Riverpod controller, auth screens, and GoRouter flow.

## One-time Firebase project setup

1. Open the Firebase Console and select the Firebase project for Testora (or create one).
2. In **Authentication → Sign-in method**, enable **Email/Password**.
3. From the project root, install/login to the Firebase CLI if needed, then run:

   ```powershell
   npm install -g firebase-tools
   firebase login
   dart pub global activate flutterfire_cli
   flutterfire configure --platforms=web
   ```

   Select the Testora Firebase project when prompted. This creates `lib/firebase_options.dart`. The repository does not include that generated file because the values must match the Firebase project and registered platform app you choose. If Android/iOS platform folders are added to this repository, rerun FlutterFire configuration for those platforms too.

4. Resolve packages and verify the app:

   ```powershell
   flutter pub get
   flutter analyze
   flutter test
   flutter run -d chrome
   ```

## What is connected

- Email/password registration and login use Firebase Authentication.
- Firebase auth-state changes restore the signed-in session and update the existing Riverpod state.
- Registration saves the supplied name to the Firebase Auth display name.
- Password reset uses Firebase's `sendPasswordResetEmail`.
- Logout signs the user out through Firebase.
- Firebase Auth errors are mapped to user-facing messages.
- The payment integration can later use the Firebase UID and ID token. Cloudflare must verify the ID token before trusting a payment API request.

## Profile data note

Firebase Email/Password Auth does not verify or persist the phone number typed during registration as the user's Firebase phone number. The Cloudflare profile API phase should persist the submitted phone/profile fields separately, tied to the authenticated Firebase UID. Never trust a UID sent in the request body when authorizing payment operations; derive the UID from the verified Firebase ID token.

## Deployment and security notes

- Firebase client configuration is generated by FlutterFire and contains app/project identifiers; it is not a Paystack secret.
- Do not put the Paystack secret key in Flutter, `firebase_options.dart`, or Git.
- Enable and configure Firebase Authentication providers in the Firebase Console before testing.
- This branch only integrates client-side authentication. It does not yet create Cloudflare Worker/D1 resources or process payments.
